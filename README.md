# 登台 DengTai · 答辩演讲计时提词工作台

> 给「要上台讲话的人」用的 PC 端工作台：课程答辩、比赛路演、组会汇报。
> 解决三件事——**超时、忘词、节奏失控**。

纯前端零依赖：双击 `index.html` 就能用，完全离线，不上传任何数据。

![讲稿工作台](docs/screenshots/01-讲稿工作台.png)

## 三个页面，一个闭环

| 页面 | 解决什么 |
|---|---|
| **讲稿工作台** | 按分段录入讲稿 → 自动统计字数、按语速换算预计用时、检测口头禅分布，提前发现"话太满"和"话太碎" |
| **提词排练** | 全屏提词器：讲稿按语速自动滚动，当前句高亮、已读句淡出；绿/黄/红三色倒计时 + 本段进度条 + 麦克风音量条 |
| **练习复盘** | 每段"计划 vs 实际"对比柱状图、"提前/超时"偏差图、总用时与口头禅密度趋势线，告诉你**哪一段在拖后腿、有没有真的在进步** |

## 核心算法

**语速模型**

```text
预计用时（秒） = 讲稿字数 ÷ 语速（字/分钟） × 60
```

字数统计按中文逐字计，连续英文/数字按 1 个词折 2 个汉字。默认语速 240 字/分钟
（正常演讲区间 200～260），可调；调整后预计用时与提词器滚动速度同步变化。

**口头禅检测**

```text
口头禅密度 = 填充词出现次数 ÷ 讲稿字数 × 100（处/百字）
```

内置 15 个高频虚词（然后 / 就是 / 这个 / 其实……）。密度 ≤ 1.0 判为"表达干净"，
1.0～2.5 "略有"，2.5～4.5 "偏多"，> 4.5 建议逐句打磨。
说明：基于词表频率统计，属启发式方法，定位是提醒你回看讲稿，而非替你下结论。

**倒计时分级**

```text
剩余 > 60s 绿灯 ｜ 0 ≤ 剩余 ≤ 60s 黄灯 ｜ 剩余 < 0 红灯超时
```

**分段计时**

排练时按"当前用时"实时定位所在分段（分段计划窗口首尾相接、无缝隙），
并把每段的**实际用时**累积下来，复盘时与计划逐段对比。

## 快捷键（提词器内）

| 按键 | 作用 |
|---|---|
| `空格` | 开始 / 暂停计时与滚动 |
| `← →` | 跳到上一段 / 下一段开头 |
| `滚轮` | 手动微调语速 |
| `M` | 开启 / 关闭麦克风音量监测 |
| `R` | 重置本次排练 |
| `Esc` | 退出提词器 |

## 数据与隐私

- 讲稿与排练记录只存在本机浏览器 `localStorage`，不上传服务器
- 麦克风仅实时计算音量，不录音、不保存
- 「导出」生成 JSON 备份，「导入」可跨机器迁移
- 首次打开内置 6 次演示排练记录（模拟一场答辩从初稿到定稿的打磨过程），
  可用「恢复演示数据」重来

## 运行

```bash
# 方式一：直接双击 index.html（推荐，零环境依赖）
# 方式二：本地起个静态服务
python -m http.server 8080   # 然后访问 http://localhost:8080
```

推荐用 Edge / Chrome 打开，按 `F11` 全屏进入提词器，观众视角更接近真实舞台。

## 自测

算法与数据层带 69 项单元测试（Node 环境，无浏览器依赖）：

```bash
node docs/test-logic.js
```

覆盖：字数统计边界、语速换算、口头禅长词优先匹配、分段时间窗连续性、
三色预警边界值、演示数据自洽性（预计用时必须落在计划 85%～100%）、
导入导出回环、增删改。
